# FullHub

FullHub — одностраничный корпоративный портал (SPA) на `HTML/CSS/JS` с ролями **администратор** и **сотрудник**.

> ⚠️ В текущем виде приложение работает полностью на клиенте и хранит данные в `localStorage` браузера. Это удобно для локального использования, демо и пилотов, но для полноценного production (мультипользовательский доступ, защита данных, аудит, резервное копирование на сервере) рекомендуется выносить логику и хранение данных на backend.

## Возможности системы

## 1) Авторизация и роли
- Вход по телефону (логину) и паролю.
- Роли:
  - **Администратор** — доступ к разделам «Сотрудники», «Смены Самара», «Смены Тольятти», «Финансы», «Аналитика».
  - **Сотрудник** — личный кабинет с KPI, сменами, историей движения средств и QR-отметкой.
- Кнопка **«Сбросить локальные данные»** на экране входа очищает хранилище и подгружает демо-данные.

## 2) Раздел «Сотрудники»
- Добавление сотрудника через форму (`+ Добавить сотрудника`).
- Поля: ФИО, должность, тип трудоустройства, форма оплаты, график, ставка/оклад, отдел, дата рождения, телефон, пароль.
- Список сотрудников:
  - отдельный режим просмотра;
  - редактирование через **шестерёнку (⚙️)**;
  - сохранение/удаление в режиме редактирования.
- Фильтры по поиску, отделу, должности.
- Справочники (должности/формы оплаты/отделы/графики) с управлением через ⚙️/💾.
- Блок ближайших дней рождения.

## 3) Раздел «Смены»
### Самара
- 3 отдельных блока:
  1) логистика,
  2) упаковка,
  3) водители.
- В каждом блоке свой календарь, выбранная дата, форма назначения, таблица смен.

### Тольятти
- Отдельный блок с собственным календарём и формой.

### Логика смен
- Поддержка форм оплаты: **сдельная / часовая / оклад**.
- Для сдельной оплаты — ввод суммы за смену, время отключается.
- Автопланирование по графикам:
  - `5/2 (с понедельника по пятницу)` → `09:00–18:00` в рабочие дни;
  - `5/2 (со вторника по субботу)` → `09:00–18:00`;
  - `5/2 (с понедельника по пятницу - свободный)` → смены без фиксированного времени;
  - `подработка` → без автопланирования.

## 4) QR-отметка прихода/ухода
- Администратор генерирует QR-код текущего дня.
- Сотрудник сканирует QR:
  - 1-й скан — начало смены;
  - 2-й скан — окончание смены.
- Если приход раньше `09:00`, в расчёт идёт `09:00`.
- Для `подработка`: при первом скане может автоматически создаться смена на сегодня.

## 5) Раздел «Финансы»
- Фильтры: месяц, период, отдел, сотрудник.
- Массовые действия по выбранным сотрудникам: выплата / премия / штраф.
- Рабочие дни по месяцам (для корректного расчёта оклада).
- История начислений/списаний (редактирование и отмена ручных операций).
- Блок открытых смен:
  - фильтр по дню/периоду,
  - выбор смен чекбоксами,
  - выбор всех,
  - ручное время открытия и закрытия.
- Блоки праздничных дней и автоштрафов.

## 6) Личный кабинет сотрудника
- Улучшенный интерфейс с упором на удобство:
  - компактные KPI;
  - QR-статус и отметка;
  - раскрывающиеся секции профиля;
  - раскрывающиеся блоки смен и истории денежных операций.

## 7) Аналитика
- KPI по сотрудникам/отделам.
- Табличная аналитика.
- Экспорт отчёта в Excel-совместимый формат.

## Технический стек и архитектура

- Frontend: `index.html`, `styles.css`, `app.js`.
- Хранение: `localStorage` (ключ: `fullhub-data-v4`).
- Версия приложения: `2026.02.27-v4`.
- Библиотеки:
  - `qrcode` — генерация QR;
  - `html5-qrcode` — сканирование QR.

### Ограничения текущей архитектуры
- Данные не синхронизируются между разными браузерами/устройствами.
- Без backend отсутствуют централизованные:
  - аутентификация и безопасные сессии,
  - журнал аудита,
  - резервные копии на сервере,
  - разграничение доступа на уровне API/БД.

- [ ] Проверить отображение на мобильных и десктопах.

### Рекомендуемый следующий этап для «настоящего» production
1. Backend API + БД (PostgreSQL/MySQL).
2. Хеширование паролей (bcrypt/argon2), JWT/сессии.
3. RBAC на сервере.
4. Серверный аудит действий.
5. Бэкапы и мониторинг.

## Публикация на hosting.timeweb

Ниже инструкция для **shared hosting Timeweb** (статический сайт).

### Шаг 1. Подготовьте файлы
В корне проекта должны быть:
- `index.html`
- `styles.css`
- `app.js`
- (опционально) `.htaccess` для правил кэша/безопасности

### Шаг 2. Создайте сайт в панели Timeweb
1. Войдите в панель Timeweb.
2. Перейдите в раздел **Сайты**.
3. Нажмите **Добавить сайт**.
4. Укажите домен (или временный поддомен Timeweb).

### Шаг 3. Загрузите файлы
Можно через:
- встроенный **Файловый менеджер**,
- **FTP/SFTP**,
- Git (если подключён в тарифе).

Загрузите содержимое проекта в корневую директорию сайта (обычно `public_html/<домен>/`).

### Шаг 4. Проверьте запуск
Откройте сайт по временному URL или домену и убедитесь, что:
- грузится `index.html`,
- стили и скрипт подгружаются без 404,
- авторизация работает.

## Привязка домена к сайту

Есть 2 сценария.

### Сценарий A: домен уже у Timeweb
1. В панели Timeweb откройте домен.
2. Привяжите его к созданному сайту.
3. Проверьте DNS-записи (обычно ставятся автоматически).

### Сценарий B: домен у другого регистратора
1. В Timeweb откройте настройки сайта/домена и посмотрите целевые DNS (обычно IP сервера или NS).
2. У регистратора домена задайте нужные записи:
   - `A` для `@` → IP сервера Timeweb,
   - `CNAME` для `www` → `@` (или хост из инструкции Timeweb).
3. Дождитесь распространения DNS (обычно от 5 минут до 24 часов).
4. После делегирования привяжите домен к сайту в Timeweb.

## SSL, кэш и базовая безопасность

### SSL
1. В панели Timeweb откройте SSL/Сертификаты.
2. Выпустите бесплатный Let’s Encrypt.
3. Включите автообновление сертификата.
4. Настройте редирект HTTP → HTTPS.

### Кэш
Чтобы пользователи всегда получали актуальный JS/CSS после релизов:
- меняйте версию в подключении скриптов/стилей (cache-busting),
- либо используйте короткий `max-age` для `index.html` и более длинный для статических ассетов с версией.

### Минимальные security headers
Если доступна настройка через `.htaccess`/панель:
- `X-Frame-Options: SAMEORIGIN`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Content-Security-Policy` (настроить аккуратно, учитывая CDN для QR библиотек)

## Обновление версии и деплой новых релизов

Рекомендуемый процесс:
1. Обновить `APP_VERSION` в `app.js` и query-параметр у скрипта в `index.html`.
2. Прогнать локальную проверку:
   ```bash
   node --check app.js
   ```
3. Проверить UI локально.
4. Загрузить файлы на Timeweb.
5. Сделать hard refresh в браузере (`Ctrl+F5`) и проверить критичные сценарии.

## Диагностика и частые проблемы

### Сайт открылся, но «старый интерфейс»
- Очистите кэш браузера (`Ctrl+F5`).
- Убедитесь, что обновили версию в `index.html` (`app.js?v=...`).

### Не работает QR-сканирование
- Проверьте HTTPS (камера в большинстве браузеров требует безопасный контекст).
- Проверьте разрешение на доступ к камере.
- Используйте fallback ручного ввода токена, если камера недоступна.

### «Пропали» данные
- Данные хранятся в `localStorage` конкретного браузера/устройства.
- Очистка браузера, режим инкогнито или смена устройства = отдельное хранилище.

### Что делать перед стартом в бою
- Удалить демо-пользователей.
- Создать реальные учётные записи.
- Зафиксировать регламент резервного копирования/экспорта.

## Лицензирование и ответственность

Использование в production без backend-слоя допускается только при понимании ограничений клиентского хранения данных и рисков безопасности.
